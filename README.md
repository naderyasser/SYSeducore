## 🎯 نظرة عامة

يُوفِّر النظام حلاً شاملاً لإدارة المراكز التي تضم مدرسين متعددين وطلاباً في مجموعات دراسية. تشمل المهام الأساسية:

| الميزة | الوصف |
|---|---|
| **إدارة الطلاب** | تسجيل بيانات كاملة، باركود/QR Code، كارنيه الطالب |
| **إدارة المدرسين** | ملف المدرس، المواد، المجموعات، الجداول |
| **تسجيل الحضور** | مسح كود الطالب، كشف الحالة الفوري، تتبع الجلسات |
| **المدفوعات** | تتبع الرسوم الشهرية، الإعفاءات، حساب مستحقات المدرسين |
| **إشعارات الواتساب** | إرسال تلقائي لتقارير الحضور والمدفوعات |
| **التقارير** | لوحة تحكم، تقارير مالية، سجل النشاط |

## 📦 الوحدات والتطبيقات

### 1. Accounts — المستخدمون

**الموقع:** `apps/accounts/`

يدير المستخدمين بنظام أدوار مدمج (RBAC):

| الدور | الصلاحيات |
|---|---|
| `admin` (مدير النظام) | صلاحيات كاملة على كل شيء |
| `supervisor` (مشرف الحضور) | تسجيل الحضور، عرض البيانات |
| `teacher` (مدرس) | عرض مجموعاته وطلابه فقط |

**الميزات الأمنية:**
- **`SystemLockoutMiddleware`** — إغلاق النظام بالكامل بتغيير متغير واحد (`SYSTEM_LOCKOUT = True`).
- **`SessionTimeoutMiddleware`** — تسجيل خروج تلقائي بعد ساعة من الخمول.
- حماية ضد CSRF، كلمات مرور مشفرة، تحديد معدل الطلبات (Rate Limiting).

---

### 2. Students — الطلاب

**الموقع:** `apps/students/`

**بيانات الطالب الكاملة:**
- الاسم، الجنس، المرحلة الدراسية (ابتدائي / إعدادي / ثانوي)، السنة، نوع التعليم (عام / لغات / تجريبي).
- أرقام هواتف (الطالب + ولي الأمر)، تاريخ الميلاد، المدرسة، العنوان.
- **كود فريد (`student_code`)** لكل طالب — يُستخدم في تسجيل الحضور.
- **باركود (Code128) وQR Code** تُوُلَّد تلقائياً وتُخزَّن في `media/barcodes/`.
- حقول اشتراك: `last_payment_date`، `subscription_expiry_date`.

**نموذج الإلحاق (`StudentGroupEnrollment`):**
يمكن للطالب الانتساب لأكثر من مجموعة (أكثر من مدرس) في آنٍ واحد، مع حالة مالية مستقلة لكل مجموعة (معفى / خاضع للرسوم).

**الحذف الناعم (Soft Delete):**
الطالب المحذوف لا يُحذف من قاعدة البيانات فعلياً، بل يُسجَّل وقت الحذف ومن قام به.

---

### 3. Teachers — المدرسون

**الموقع:** `apps/teachers/`

يحتوي على عدة نماذج مترابطة:

#### `Teacher` — المدرس
- الاسم، الهاتف، البريد الإلكتروني، تاريخ التعيين.
- صورة شخصية (مطلوبة لطباعة ظهر كارنيه الطالب).
- اشتراك في المواد الدراسية عبر علاقة Many-to-Many.

#### `Subject` — المادة الدراسية
- اسم المادة ومرحلتها الدراسية.

#### `Room` — القاعة الدراسية
- اسم القاعة وسعتها القصوى.

#### `Group` — المجموعة الدراسية
- مرتبطة بمدرس وقاعة.
- يوم الحصة ووقتها ومدتها (بالدقائق).
- تصنيف الجنس (بنين / بنات / مختلط).
- المرحلة الدراسية والصف.
- **`center_percentage`** — نسبة المركز من الإيرادات لحساب مستحقات المدرس.
- كشف تعارض الجداول: يمنع حجز نفس القاعة في وقتين متداخلين.

#### `GroupSchedule` — مواعيد المجموعة
جدول مرونة يسمح بتعدد مواعيد الحصة خلال الأسبوع.

---

### 4. Attendance — الحضور

**الموقع:** `apps/attendance/`

#### `Session` — الجلسة الدراسية
تُنشأ تلقائياً عند تسجيل أول حضور ليوم معين، وترتبط بمجموعة ويوم محدد (unique_together).

#### `Attendance` — سجل الحضور
- حالات: `present` (حاضر) / `late` (متأخر) / `absent` (غائب).
- وقت المسح، المشرف المُسجِّل.

#### `AttendanceService` — خوارزمية الحضور
الخوارزمية تسير في **4 خطوات صارمة**:

```
1. التحقق من وجود الطالب (كود صحيح؟)
2. التحقق من تسجيل مسبق في نفس الجلسة (منع التكرار)
3. الكشف الفوري: هل دفع الشهر الحالي؟ هل عليه متأخرات؟
4. تسجيل الحضور بالحالة المناسبة (حاضر / متأخر)
```

قواعد الوقت:
- **30 دقيقة** قبل بداية الحصة = مسموح بالدخول.
- **10 دقائق** بعد بداية الحصة = الحد الفاصل بين "حاضر" و"متأخر".

#### `ActivityLog` — سجل النشاط الكامل
يسجل كل عملية في النظام (إنشاء/تعديل/حذف) مع اسم المستخدم والوقت، لضمان المساءلة الكاملة.

---

### 5. Payments — المدفوعات

**الموقع:** `apps/payments/`

#### `Payment` — الدفعة
- مرتبطة بطالب، مجموعة، وشهر محدد (unique_together).
- المبلغ المطلوب، المبلغ المدفوع، حالة الدفع (مدفوع / جزئي / غير مدفوع).
- عدد الحصص المحضورة وإجمالي الحصص في الشهر.

#### `SettlementService` — حساب المستحقات
يحسب مستحقات المدرس لشهر محدد:

```
إيرادات المجموعة × (100% - نسبة المركز%) = حصة المدرس
```

يعمل مع كل مجموعات المدرس ويقدم تقسيم مفصل لكل مجموعة.

---

### 6. Notifications — الإشعارات

**الموقع:** `apps/notifications/`

#### `WhatsAppMessage` — رسالة الواتساب
يتتبع النظام كل رسالة واتساب: المُرسَل إليه، النص، النوع (للطالب / لولي الأمر / جماعية / تقرير)، والحالة (معلقة / مُرسلة / فاشلة / مُسلَّمة).

**الإرسال التلقائي (Celery):**

| المهمة | الجدول |
|---|---|
| إرسال إشعارات حضور | كل 5 دقائق |
| تذكير رسوم شهري | أول كل شهر الساعة 9 صباحاً |

**API المستخدمة:** WaSender API (متغير `WASENDER_API_TOKEN`).

---

### 7. Reports — التقارير

**الموقع:** `apps/reports/`

لوحة تحكم مركزية تُعرِض:
- إحصائيات عامة (إجمالي الطلاب، الحضور، الإيرادات).
- تقارير مالية شهرية وسنوية.
- تقارير حضور مفصلة لكل مجموعة.
- سجل نشاط المستخدمين.

**حماية التقارير الحساسة:**
تتطلب بعض التقارير كلمة مرور منفصلة (`REPORTS_PASSWORD`) حتى للمستخدمين الذين قاموا بتسجيل الدخول (المديرون معفيون).

---

### 8. Core — البنية التحتية

**الموقع:** `apps/core/`

#### `SoftDeleteModel` (Abstract)
نموذج مجرد تُرِثه كل النماذج الداعمة للحذف الناعم:
- `deleted_at` — وقت الحذف.
- `deleted_by` — من قام بالحذف.
- `objects` — يُرجع السجلات الحية فقط.
- `all_objects` — يُرجع الكل بما فيه المحذوف.
- `soft_delete(user)` / `restore()` — دوال الحذف والاستعادة.

User ─────────────────────────────────────────────────┐

## 🔐 الصلاحيات والأمان

| الميزة | التفاصيل |
|---|---|
| RBAC | 3 أدوار: admin, supervisor, teacher |
| Session Timeout | تسجيل خروج بعد ساعة خمول |
| Rate Limiting | `django-ratelimit` على صفحات الدخول والـ API |
| CSRF Protection | محمية على كل العمليات |
| HSTS | مفعّل في الإنتاج مع `includeSubDomains` + `preload` |
| X-Frame-Options | DENY (حماية من Clickjacking) |
| System Lockout | إغلاق كامل للنظام بمتغير بيئة |
| Soft Delete | البيانات لا تُحذف نهائياً، كل حذف موثق |
| Activity Log | كل عملية مسجلة مع المستخدم والوقت |

## ⚙️ التثبيت والتشغيل

### متطلبات التطوير

- Python 3.11+
- Redis (اختياري، مطلوب لـ Celery)

### خطوات التثبيت

```bash
# 1. نسخ المستودع
git clone <repo-url>
cd SYSeducore

# 2. إنشاء بيئة افتراضية
python -m venv venv
source venv/bin/activate

# 3. تثبيت المتطلبات
pip install -r requirements.txt

# 4. إنشاء ملف البيئة
cp .env.example .env
# ثم تعديل القيم داخل .env

# 5. تهيئة قاعدة البيانات
python manage.py migrate

# 6. إنشاء مستخدم مدير
python manage.py createsuperuser

# 7. تشغيل السيرفر
python manage.py runserver
```

### تشغيل Celery (الإشعارات التلقائية)

```bash
# worker
celery -A config worker -l info

# beat scheduler
celery -A config beat -l info --scheduler django_celery_beat.schedulers:DatabaseScheduler
```

## 🚀 النشر على الإنتاج

يستخدم النظام Docker Compose مع ثلاث خدمات:

```
┌─────────────────────────────────────────┐
│  Nginx (Port 80/443)                    │
│  - Reverse Proxy                        │
│  - SSL Termination                      │
│  - Static Files Serving                 │
│  - Rate Limiting (10 req/s API)         │
└──────────────┬──────────────────────────┘
               │
┌──────────────▼──────────────────────────┐
│  Django / Gunicorn (Port 8000)          │
│  Workers: 4                             │
└─────┬──────────────┬────────────────────┘
      │              │
┌─────▼──────┐  ┌────▼───────────────────┐
│ PostgreSQL │  │ Redis                  │
│ Port 5432  │  │ Port 6379              │
│ (Database) │  │ (Cache + Celery Broker)│
└────────────┘  └────────────────────────┘
```

```bash
# تشغيل الكل
docker-compose up -d

# مراقبة اللوغات
docker-compose logs -f web
```

## 📋 ملاحظات هامة

- **اللغة:** النظام بالكامل بالعربية (locale: `ar-eg`، timezone: `Africa/Cairo`).
- **المنطقة الزمنية:** القاهرة — جميع الأوقات محسوبة محلياً.
- **الحذف:** لا يُحذف أي سجل مهم نهائياً من قاعدة البيانات.
- **الإيرادات:** النظام يحسب مستحقات كل مدرس تلقائياً بناءً على النسبة المتفق عليها مع المركز.
- **API الواتساب:** النظام يستخدم WaSender كمزوّد رئيسي مع دعم UltraMsg كخيار قديم.
